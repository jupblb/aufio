# KA17 protocol and this setup

These notes distinguish observed hardware behavior from source-derived details. Research and local validation date: **2026-09-17**.

## Connected hardware

- Host: Apple Silicon macOS; the only supported platform for this project.
- DAC: FiiO KA17, USB VID `0x2972`, PID `0x0093`.
- USB `bcdDevice` / HID release: `0x0225` (decimal 549), consistent with firmware 2.25. This is a USB revision observation, not a separately queried firmware string.
- No USB serial number is exposed by this unit. A path identifies it only for the current attachment. Use `inspect` after reconnection.
- Control interface: 3, usage page 1; macOS also enumerates media keys at the same path (usage page 12). Deduplicate paths and select the control collection.
- Headphones: **HiFiMan Arya Unveiled**. Do not substitute Arya, Arya Stealth or Arya Organic measurement profiles. No headphone measurement/target curve has been selected or applied by this project.

## HID framing confirmed on this Mac

HID report ID **1**, output payload **32 bytes**, zero padded. `node-hid`/HIDAPI writes include the report-ID byte, for 33 bytes total. Input messages received on this Mac contain the report ID; validate the meaningful packet length rather than assuming every input report has exactly the descriptor’s maximum length. Media-key messages use report ID 2 and must not be parsed as EQ responses.

Descriptor observed with macOS `ioreg`:

``` text
05010900a1018501150025ff19012908952075088102190129089102c0
050c0901a10185021500250109cd09b509b609e909ea09e275019506810295028101c0
```

Payload, excluding report ID:

``` text
Read:  BB 0B 00 00 command length [data] 00 EE
Write: AA 0A 00 00 command length [data] 00 EE
```

| Command | ID | Payload |
|----|----|----|
| Band | `15` | Read: zero-based index; write: index, signed gain16, frequency16, Q16, type |
| Preset | `16` | Read: empty; select: slot byte |
| Preamp | `17` | Read: empty; write: signed gain16 |
| Band count | `18` | Read: empty; write: count byte |
| Save to device | `19` | Destination user-slot byte |

All multibyte values are **big-endian**. Gains use signed two’s-complement, 0.1 dB units; frequency uses integer Hz; Q uses 0.01 units. Examples:

``` text
Read current slot: BB 0B 00 00 16 00 00 EE
Set preamp −5.1:   AA 0A 00 00 17 02 FF CD 00 EE
Save USER1:        AA 0A 00 00 19 01 04 00 EE
```

Read responses use `BB 0B`, carry the command and length, and echo the band index. Match all of these, not arrival order. Commands are spaced 200 ms apart, following the vendor KA17 queue. Native non-exclusive access works on the tested Mac.

## Preset and filter IDs

USER1=`4`, USER2=`8`, USER3=`9`, BYPASS=`10`. Factory presets: Jazz=`0`, Pop=`1`, Rock=`2`, Dance=`3`, R&B=`5`, Classic=`6`, Hip-hop=`7`. **Slot 7 is not writable user storage.** The reference’s `firstWritableEQSlot: 7` is inconsistent with its own labels; the captured vendor app and observed USER1 read both confirm `4`. Use an explicit allowlist.

Band/preamp reads address the **active working EQ**, not an arbitrary stored slot. aufio requires the destination USER slot to be active, backs it up, writes the fields, verifies at −12 dB preamp before raising gain, verifies the final values, sends save, then reads again. A save response or power-loss persistence has not been established; readback must not be reported as proof of flash storage.

Vendor filter enum: peak=`0`, low shelf=`1`, high shelf=`2`, band-pass=`3`, low-pass=`4`, high-pass=`5`, all-pass=`6`. The app’s KA17 path exposes all seven; official V2.00 notes independently confirm LP/HP additions. The source capture does not demonstrate BP/AP on KA17. Initial aufio tuning supports PK/LS/HS only; raw snapshot restoration preserves all recognized types without translating them. Unknown IDs fail rather than silently becoming a peak.

Hardware EQ OFF is **not** positively mapped. The vendor app skips its generic `0x1A` EQ switch for KA17. BYPASS slot 10 is not proof that EQ processing is OFF. Do not claim to have queried or changed the independent hardware EQ power state.

## Q and headroom conventions

The reference reports a KA17 measurement at 1 kHz, +6 dB, Q=1 consistent with:

``` text
Q_realized = Q_stored / 10^(abs(gain_dB) / 40)
```

`qMode=rbj-peak` applies the inverse for peaking filters only. Exact backups retain raw Q values; `save` emits `qMode=device`, preventing accidental double compensation. KA17 shelf compensation is not established, and QX13 shelf findings are not automatically applied. Headroom uses an approximate combined RBJ response across 44.1/48/96/192 kHz with center frequencies included in the scan. It recommends 1 dB additional margin but cannot guarantee the real device’s response or inter-sample headroom. No acoustic measurements were taken in this project.

Original active slot: USER1. Ten bands, preamp **−7.6 dB**. Original user preset is `arya-original`; the initial durable raw backup is:

``` text

```

Verified native enumeration, complete reads, local saving, a temporary −0.1 dB preamp/first-band change, save-command transmission, fresh-process readback, restoration, and exact comparison against the original state. The device was left on USER1 with its original EQ. No playback-volume, amp-gain or firmware commands were sent.

Still unverified: physical power removal/reconnection, switching to other slots, and acoustic filter response. To investigate alleged memory loss, record live state **before** reapplying anything after reconnection. Disconnect external power as well as the data cable when testing genuine power loss.
